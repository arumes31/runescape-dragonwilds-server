# Upstream issue and pull request review

Reviewed 2026-09-22 against upstream main `3047d4663b44fabec506f71411182d387b450456`: six open issues, three open PRs. Changes are in this local branch; no upstream issues were closed and no upstream PRs were merged.

| Item | Findings and local disposition |
| --- | --- |
| [#1 Startup crashes](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/issues/1) | Reports have different causes: malformed owner IDs, permissions, duplicate processes and native Unreal crashes. Added early owner/config validation, non-root execution, ownership repair, exact signal forwarding and process/UDP probes. Failures now remain stopped instead of rebooting indefinitely. Native game crashes cannot all be declared fixed by this wrapper. |
| [#2 Kicked to menu / Unraid](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/issues/2) | Maintainer identifies mismatched ports; comments also confirm firewall failures and proxy/NAT concerns. Compose maps equal host/container ports, adds the documented beacon port (game +1111), and validates their relationship. Real-game testing also exposed the need to set OnlineBeaconHost.ListenPort explicitly; this now works with nondefault ports. External firewall, routing and in-game joins still require deployment/client verification. |
| [#4 Variables appear empty / world overwritten](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/issues/4) | Explicit Compose environment mapping and environment-driven INI merging remove template/export ambiguity. Default world values and special characters have regression coverage. Empty `WorldOwnerName` in game logs is not proof that `OwnerId` is missing; no undocumented OWNER_NAME variable was invented. |
| [#5 Oracle ARM download error](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/issues/5) | Native game payload is Linux x86_64. Documented as unsupported on ARM and added Linux deployment architecture preflight. Replaced normal installs with Valve SteamCMD and explicit failure handling. This does not make the proprietary game ARM-native or establish an Oracle emulation fix. |
| [#8 Inline world-name comment](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/issues/8) | Standalone comments in the sample; Compose handles .env parsing. Control characters / embedded whitespace-plus-comment world names fail early instead of becoming bad save names. Literal password special characters remain intact. |
| [#9 Don't pause when empty](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/issues/9) | The cited log is from the game's GameMode. No supported override was verified in the official guide or container. Unresolved game capability; not falsely marked fixed and no process-suspension workaround added. |
| [PR #3 World-name documentation](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/pull/3) | Applied the intent in a dedicated README explanation, including the distinction between new-world name, existing saves and server display name. |
| [PR #6 Preserve GUID / known players](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/pull/6) | Implemented a broader preserving merge: GUID, repeated KnownPlayerList, custom keys and other sections all survive. Tested restarts and literal values. No ban roster is reconstructed from an incomplete environment string. |
| [PR #7 Don't regenerate INI](https://github.com/indifferentbroccoli/runescape-dragonwilds-server-docker/pull/7) | Added `GENERATE_SETTINGS=false` for an untouched existing INI and compatibility with the proposed direct-run alias. Default remains a preserving merge so intended environment changes take effect. First-boot creation is covered. |

Additional defects corrected: ignored downloader failures, overly broad process matching, fragile quoted multi-PID kill behavior, split shell arguments, missing in-game admin password validation, incomplete port health checks, missing beacon exposure, and lack of reliable installed Steam build metadata.

The publisher's container source confirms the beacon and manifest/update approach: https://github.com/runescape/rsdw-dedicated . The publisher guide confirms world-name lookup and in-game moderation: https://dragonwilds.runescape.com/news/how-to-dedicated-servers .
